# ADR-0002 — Phase 2: Model Router / Provider Layer

## Status
Implemented (Phase 2 complete). Phase 3 governance is documented in ADR-0003.

## Context
Phase 1 established the modular monolith foundation (FastAPI, SQLAlchemy, three DB roles, import-linter boundaries). Phase 2 adds the provider abstraction layer that all future agent work depends on. The architecture document designates `apps/gateway` as the sole privileged process holding provider credentials.

## Decisions

### 1. Provider Abstraction
- All routing logic lives in `core/model_router/` (DDD-layered: domain → application → infrastructure).
- All provider I/O lives in `apps/gateway/` (adapters, pipeline, routes).
- `core/model_router/domain` and `core/model_router/application` are forbidden from importing `httpx`, `fastapi`, `sqlalchemy`, `psycopg` (enforced by import-linter contract #7).

### 2. Stable model_id vs. provider_model_id
- `ModelSpec.model_id` is an internal stable identifier (e.g. `deepseek-chat-v3`).
- `ModelSpec.provider_model_id` is the provider's own identifier (e.g. `deepseek-chat`).
- A `UNIQUE (provider, provider_model_id)` constraint enforces no collisions.
- Callers always use `model_id`; adapters translate to `provider_model_id` internally.

### 3. Adapter pluggability
- `BaseProviderAdapter` (ABC in `apps/gateway/adapters/base.py`) is the extension point.
- New providers: subclass `BaseProviderAdapter`, register in the `adapters` dict passed to `ExecutionPipeline`.
- DeepSeek is the only Phase 2 adapter; OpenAI, Anthropic, and local models can be added without breaking changes.

### 4. Retry and circuit-breaker policy
- Max 3 total execution attempts (2 retries) with exponential backoff and ±20% jitter.
- Retryable: `ProviderTransientError`, `httpx.TransportError`, `httpx.TimeoutException` (network and 429/5xx).
- Not retryable: `ProviderValidationError` (400), `ProviderAuthError` (401/403), `ProviderClientError` (other 4xx).
- Not retryable, do not trip circuit breaker: validation and auth errors.
- Streaming calls are not retried once initiated.
- Circuit breaker: CLOSED → OPEN at `failure_threshold` consecutive transient failures, HALF-OPEN after `cooldown_seconds`.

### 5. JSON Schema validation for structured output
- `jsonschema==4.23.0` (MIT) validates the parsed JSON payload against `request.response_schema`.
- Validation errors are wrapped as `ProviderValidationError` (not retried, not circuit-broken).
- Error messages describe the schema violation; no raw provider payload is included.

### 6. Cost tracking
- All financial arithmetic uses Python `Decimal`; no float is used.
- `cost_ledger` rows are append-only; the `app` role has `INSERT, SELECT` only.
- Token/cost columns are `NULL` (not zero) when a call fails before the provider reports usage.
- `cost_ledger.id` is a UUIDv7 (time-ordered) generated by `core/model_router/domain/ids.py`.
- `uuid6==2024.1.12` (MIT) is the only external library used for UUIDv7; all callers go through `new_uuid7()`.

### 7. D4 database security
- `migrator` role owns all schema (CREATE TABLE, CREATE INDEX, GRANT).
- `app` role DML: `SELECT` on `model_registry`, `INSERT + SELECT` on `cost_ledger`.
- No `UPDATE` or `DELETE` ever issued by application code.
- Grants are issued in migration files run by `migrator`.

### 8. Internal gateway authentication
- `X-Internal-Secret` header validated on every gateway route (fail-closed).
- Missing, empty, or incorrect header → 401 immediately, before any business logic.
- The secret is stored as `SecretStr`; `hide_input_in_errors=True` prevents it from appearing in Pydantic validation errors.

## Production security requirements (not built in Phase 2)
The following controls are required before production traffic flows through the gateway:

1. **HTTPS / TLS termination** — the gateway must not accept plaintext HTTP from other services in production. Use mTLS between workers and the gateway, or terminate TLS at an internal load balancer.
2. **Request signing** — `X-Internal-Secret` is a shared secret; replace with asymmetric request signing (e.g. HMAC-SHA256 over the request body + timestamp) to prevent replay attacks.
3. **Gateway not exposed to host network** — in the development Compose stack, the gateway service has no published ports. In production, the gateway must be on an internal network segment only; no public ingress.
4. **Provider key rotation** — `deepseek_api_key` should be injected from a secrets manager (e.g. AWS Secrets Manager, HashiCorp Vault), not from a plain environment variable, in production.
5. **Rate limiting on internal routes** — the internal `/internal/model/*` endpoints should be rate-limited to prevent a misconfigured worker from overwhelming the provider.

## Deferred
- OpenAI, Anthropic, and local model adapters (pluggable, no breaking changes needed).
- `run_id` and `step_id` in `cost_ledger` — nullable; will be populated once the Worker and Step table exist (Phase 4+).
- `reporting` DB role — deferred per ADR-0001 until the process that uses it exists.

## Completed in Phase 3 (was deferred here)
- Governance admission check — `GovernancePort` injected into `ExecutionPipeline`; `GovernanceDeniedError` is never retried. See ADR-0003.
- `governance` DB role — provisioned in Phase 3. See ADR-0003.
